## 之前功能

1. 希望交貨日期不可選擇昨天或更早的日期。
2. 訂購人可選擇「記住我的資料」；儲存角色名稱、伺服器、聯絡方式到自己的瀏覽器，不保存備註、交貨日期及交易時段。
3. 訂單查詢收據新增「再訂一次」：已下架的商品與裝備／客製委託不會自動帶入；商品更改售價以目前設定為準，並提示差異。
4. 正式送出前新增羊皮紙確認視窗，顯示品項、數量、已知 Gil 小計、待報價項目與訂購人資訊；可返回修改。
5. 新增前端隱藏欄位（honeypot）阻擋部分機器人；這只是基本防護，不足以阻擋針對性大量送單。
6. 選用 Google Apps Script 更新：新訂單 Discord 通知、同角色短時間重複送單防護。預設均停用，不影響原接單流程。
7. `index.html`、`orders.html` 及靜態資源參數升級為 1.3.77。

## V1.3.92｜客製委託金額連動
- 訂單總表 M 欄「最後報價 Gil」依訂單編號加總客製委託 J 欄，但排除 H 欄「固定售價」（此類已包含 I 欄）。
- 空白報價維持空白；未分配的統一報價將合計數字僅記在其中一筆 J 欄，並以儲存格附註說明。
- 新委託送入後，`Code.gs` 自動為需報價委託新增 M 欄連動公式。舊委託空白 M 可透過 `linkEmptyAngulusFinalQuotes()` 安全補上。
- Google Apps Script 程式須重新儲存並更新 Web App 部署；不影響既有收據／Discord 同步邏輯。


## V1.3.95｜客製委託小計自動計算
- 「客製委託」J 欄：非固定售價的新項目預設公式 `=IF(OR(H2="固定售價",I2="",G2=""),"",I2*G2)`（列號依實際列調整）。
- 固定售價項目由接單時的價格表驗價並寫入小計，不會套用或覆蓋公式。
- 統一報價可留一列 J 欄手動輸入整筆總額，其他列留空並加附註；舊資料不覆蓋。
- 對既有資料可手動執行 `installAngulusCommissionSubtotals()`，只補空白且未註記的非固定價委託列。
- 訂單總表 M 欄繼續加總同編號且非固定售價的客製項目 J 欄。
- 需更新 Apps Script 網頁應用程式版本；網站本身只有版本標示變更。


### V1.3.95 後端寫入修復
修正多表 `getLastRow()` 受到跨分頁 `ARRAYFORMULA` 影響，導致混合訂單明細在約第 1000 列新增、不易察覺的問題。新版本改用 A 欄實際訂單編號定位下一筆，並套用到商品、客製、回執、Discord 紀錄。

## V1.3.96｜客製委託項目名稱排版
- 客製委託 C 欄（項目名稱）固定 365 px，設自動換行、靠上對齊。
- 以全形「／」作換行分界，保留斜線本身；例如「雀翎套裝／散件」顯示兩行。
- 新接單時後端自動插入換行並調整新增委託列高；不改動價格與其他資料。
- 既有六筆資料已直接更新線上工作表。
- 要讓後續新委託自動按「／」分行，需要更新此版 Code.gs 的 GAS 網頁應用程式部署。


## V1.3.98｜客製委託項目名稱精簡
「客製委託」B 欄已標示委託類型，因此新訂單寫入 C 欄時，自動移除項目名稱開頭重複的「【裝備訂製】」，保留套裝名稱與「／」換行。例如「雀翎套裝（750/7.3）／\n散件」。僅調整試算表顯示名稱，不修改商品內容、金額、客製類型或其他資料。
需部署新版 Code.gs 才能讓未來訂單自動套用。


## V1.3.98 — 訂單總額與收據
- 訂單總表 L 欄後新增 M「訂單總額 Gil」，M=K 固定商品小計+L 最後報價，原 M:O 移至 N:P。
- 查詢收據的「委託小計」移到店主最終報價後方，讀取訂單總額。

- 配合試算表欄位變更，必須部署新版 Code.gs，並將更新後的 orders.html、order-lookup.js 上傳 GitHub Pages。


## V1.3.99｜整體檢查修正版
